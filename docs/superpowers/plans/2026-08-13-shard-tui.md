# Shard TUI and launcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the `shard` launcher and a dependency-free interactive terminal UI while preserving the existing `shardcode run`/`resume` lifecycle and safety boundaries.

**Architecture:** The CLI parser will distinguish interactive mode from explicit commands and bare task shorthand. A focused `tui.ts` module will own terminal input, ANSI rendering, output sanitization, and permission prompts through injectable interfaces. `main.ts` will adapt the TUI to the existing `CliIO` and reuse the same runtime construction path for all task execution.

**Tech Stack:** TypeScript strict, Node.js standard `readline/promises` and process streams, ANSI terminal control sequences, Vitest, pnpm workspaces.

## Global Constraints

- `runtime` remains the only package that orchestrates `context-engine`, `tool-runtime`, `memory`, `sandbox`, and `providers`.
- CLI code must not perform filesystem, shell, or Git operations directly; all task actions continue through `ToolRuntime`.
- No new TUI dependency is introduced in V1.
- `shard` and `shardcode` share one entrypoint; explicit `run`, `resume`, `--help`, JSON output, permissions, budgets, and session behavior remain supported.
- Human-readable terminal output must strip ANSI/control sequences originating from tool or model output before rendering.
- Every behavior change gets a failing test before its production implementation.

### Task 2: Build the dependency-free TUI boundary

**Files:**
- Create: `packages/cli/src/tui.ts`
- Create: `packages/cli/src/tui.test.ts`
- Modify: `packages/cli/src/render.ts`

**Interfaces:**
- `TuiTerminal` exposes `isTTY`, `open(workspaceRoot)`, `question(prompt)`, `confirm(question)`, `write(line)`, `error(line)`, `finish(exitCode)`, and `close()`.
- `TuiExecutionIO` exposes `write(line)`, `error(line)`, and `ask(question, request?, decision?)`.
- `runInteractiveTui(options: { terminal: TuiTerminal; workspaceRoot: string; execute(prompt: string, io: TuiExecutionIO): Promise<number> }): Promise<number>` collects a non-empty prompt, invokes `execute` once, forwards output and permissions, and returns the executor exit code.
- `createDefaultTuiTerminal()` uses Node `readline/promises` and process streams; it creates and closes each readline interface around one question so permission prompts cannot share a live input interface.

- [ ] **Step 1: Write failing TUI tests**

Use a fake `TuiTerminal` with a queued `question` result and record calls. Test that an empty answer writes a validation message and asks again, a valid answer reaches `execute`, executor output reaches `write`, permission asks reach `confirm`, `finish` receives the exit code, and `close` always runs. Test that `isTTY: false` returns `1` without invoking `execute`.

- [ ] **Step 2: Run the focused test and verify it fails**

Run: `pnpm exec vitest run packages/cli/src/tui.test.ts`

Expected: failure because `tui.ts` and `runInteractiveTui` do not exist.

- [ ] **Step 3: Implement the TUI boundary**

Implement the prompt loop and lifecycle cleanup. The default terminal redraws a compact header, workspace, bounded recent event list, and final status with ANSI clear/home sequences. Keep at most 200 rendered lines and truncate each sanitized line to 4,000 characters. When the terminal is not interactive, report an error and fail closed.

- [ ] **Step 4: Add output sanitization and verify its test**

Export `sanitizeTerminalText(value: string): string` from `render.ts`. Remove ANSI escape sequences and non-printing control characters while preserving newlines and tabs. Human rendering uses this helper; JSON mode continues to serialize the original event object. Add a focused assertion for colored text and control characters, then run:

```bash
pnpm exec vitest run packages/cli/src/tui.test.ts packages/cli/src/render.test.ts
```

Expected: all TUI and renderer tests pass.

- [ ] **Step 5: Commit the TUI boundary**

