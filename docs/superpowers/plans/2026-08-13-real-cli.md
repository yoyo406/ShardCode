# Real CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a working `shardcode run`/`resume` CLI that drives a normalized multi-provider coding loop through permission-checked tools and persisted sessions.

**Architecture:** A pnpm TypeScript monorepo keeps shared contracts at the bottom. `runtime` orchestrates providers, context, memory and tools; `tool-runtime` is the only package allowed to execute filesystem, shell and Git operations. The CLI only parses arguments, renders events and supplies permission answers.

**Tech Stack:** Node.js 24+, TypeScript strict, pnpm workspaces, native `fetch`, Node `readline`, Vitest, no provider SDK dependency.

## Global Constraints

- No `packages/providers/*` package is imported by `tool-runtime` or `context-engine`.
- No filesystem, shell or Git execution occurs directly in `runtime` or `cli`.
- V1 repository search is agentic (`glob`, `grep`, `read_file`, `list_files`); no embeddings or vector database.
- A failed `ToolExecution` is returned as an observation and is never retried by runtime.
- `.git`, `.env`, secret directories and paths outside the workspace are always denied.
- `pnpm build`, `pnpm test` and `pnpm lint` must exist and be runnable from the repository root.

## File map
